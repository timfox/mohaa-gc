# MOHAA in-game cutscenes

## m1l1 opening ride

**Tag data and path progression work in Dolphin. Scripted truck models now have animated Studio MDLs, but the new meshes and animation playback still need a runtime capture.**

The runtime log shows the retail m1l1 script loading 5 tagged models and 65 animation lengths, joining as Allies Rifleman, and reading a moving `truck2` tag path through to its endpoint. See [the tag-motion report and capture](../media/2026-11-22-m1l1-tag-arena/README.md).

The first render-binding pass is in the source and has compiled into a GameCube DOL from an isolated copy of the locally available HL1 engine source:

- `script_model` and `script_object` now spawn as `CBaseAnimating` entities; `script_origin` remains an invisible `info_target`.
- `c_model` still selects the baked tag data and now assigns an MDL to renderable script models when its TIKI appears in `maps/<map>.models`.
- The backend reads that manifest and precaches the MDLs in the GameCube `ServerActivate` hook before the first mission frame.
- The exporter keeps single-weight SKD skeletons and writes each TIKI animation alias as a Studio v10 sequence. Two body choices per surface let the runtime match TIKI init and per-alias `+nodraw`/`-nodraw` entry actions; the visible-surface bitmask is stored in the scripted model's sequence metadata. The `anim` callback selects the sequence and applies its bodygroups while preserving tag sampling and `animdone` timing.

The m1l1 German Afrika private is staged as a composite Studio model. The exporter merges the body, covered head, hands, helmet, loadout and KAR clip by bone name into a 72-bone rig and remaps its four-influence vertex weights. It keeps all ten aliases called on the actor by the retail script: `opel_driver`, the three `*_killvisa` aliases, the three `*_getvisa` aliases, and the three `*_idlevisa` aliases. The generated 552,324-byte model has 3,400 triangles, nine bodygroups and ten parsed sequences; largest sequence payload is 55,332 bytes. The staged `maps/m1l1.models` manifest includes this actor TIKI. On spawn, the MOHAA binding assigns a matching precached MDL to tracked mission actors; `model` and `anim` commands can update their Studio model, sequence and surface bodygroups. Scripted grunts remain under mission control while the TIKI model is active. The stage and parsed model are under `/tmp/mohaa-composite-ten-stage/xash3d/mohaa/`; no GameCube runtime capture has confirmed its appearance or animation yet.

Its engine source came from a local HL1 worktree whose shared Git metadata is unavailable, so this is compile/link evidence rather than a build against the canonical shared engine revision; that DOL predates the new sequence exporter and playback callback. On 2026-11-23, the changed MOHAA server/client sources (`dod_mohaa.c`, `dod_mohaa.h`, and `dod_mohaa_ents.cpp`) compiled into scratch GameCube archives, and the engine linked a fresh 7,752,096-byte DOL with the classic libogc stack. Its SHA-256 is `d42b8d78675fad19cd86d120f5a7b6db4b59d56b6a9290c6c25ce17ec823070e`. The engine source was copied from the local HL1 worktree without canonical Git metadata; the missing MultiEmulator and `library_suffix` dependencies came from other local snapshots. A clean local mainui snapshot replaced the stale source in the scratch copy, and `check-menu-provenance.sh --dol` now passes. Treat this as compile/link evidence for the updated game code, not a canonical engine build: the exact engine and mainui revisions are not recorded from their original Git metadata. The first Dolphin probe of this artifact stopped before the map; the later matched-layout probe below reaches `MAP_READY`. The artifact and build logs are under `/tmp/mohaa-current-build-20261123/`.

`tools/mohaa_tiki_model.py` bakes `vehicles/gmctruck_opening.tik` as a Studio v10 model with 52 bones, 3 sequences (`idle`, synthetic `idlenolights`, `open_gate`), 13 surface bodygroups and 5,171 triangles. The synthetic alias reuses the retail idle SKC and TIKI init visibility because the m1l1 script calls `idlenolights`, which this retail TIKI does not declare. `vehicles/opeltruck.tik` has 57 bones, 6 sequences (`idle`, `idlelights`, `idlenolights`, `skidding`, `start_wheels`, `stop_wheels`), 11 bodygroups and 4,659 triangles. Fresh models were written under `/tmp/mohaa-tiki-visibility-stage/xash3d/mohaa/` and parsed by `dod-gc/tools/split_studio_mdl.py info`; they are 302,860 and 244,760 bytes. The `scriptmodels` stage in `tools/mohaa_sd.py` writes both to the user's SD game directory and creates `maps/m1l1.models`. Retail-derived outputs stay on the SD card and are not committed.

The 2026-11-23 probes first exposed a build-profile mismatch, rather than an edict-allocation failure. The engine initialized its static 900-edict tables, then rejected the MOHAA game archive because `playermove_t` was compiled as 600/64 in the engine and 256/32 in the game DLL. The scratch engine's `wscript` only honored the reduced caps for the `dod` profile, not `mohaa`. A temporary, isolated change made the MOHAA profile apply the same 256/32 caps while preserving its 900-edict limit. It produced `/tmp/mohaa-current-build-20261123/engine-debug-out/bin/mohaagc.dol` (7,752,896 bytes; SHA-256 `599b479330f047f7f84cedbb23ece39f86b7255c88e6790fe88d2de7d6cc64c1`). This uses a scratch copy of local engine sources without recoverable canonical Git metadata; the profile fix has not been applied to the shared engine checkout.

With the matching layout, Dolphin completed server/client game initialization, loaded m1l1, and reached `MAP_READY m1l1`. At entity spawn it logged 64 KiB heap free and 12 KiB unclaimed; after deferred client initialization it logged about 100 KiB free and 12 KiB unclaimed. The final 640×480 capture is 100% black. The log then identifies a connection failure: the listenserver's loopback client is refused with `GameCube DoD network v1 required`, followed by world unload. This proves map startup, but not a stable visible session or truck animation; resolve the game-specific network handshake before treating the black frame as a renderer diagnosis. Probe logs and the black frame are under `/tmp/mohaa-runtime-probe/playtests-debug/` and `/tmp/dodgc-probe-20261123-124140.log`.

The SKC reader decodes every per-bone frame, and both the tag baker and MDL exporter use that shared decoder. Retail data has `opel_opening.skc` at 6 frames / 10 fps and `opel.skc` at 1 frame / 25 fps. The converted TIKI visibility states now match the retail init and sequence entries: GMC `open_gate` reveals the scripted panels, Opel `idle`/`idlelights`/`idlenolights` switch the light surface, and wheel aliases switch between moving and still wheel meshes.

The vehicle meshes use single-bone weights. The exporter writes Xash's four-influence Studio v10 skin records, follows recursive TIKI animation includes, and can restrict an export to mission-used aliases. The German Afrika private composite replaces the earlier three-alias stage above with the complete ten-alias set used by `maps/m1l1.scr`; its model inspector output and `maps/m1l1.models` manifest are recorded above. This is conversion and source-integration evidence only: no runtime capture has yet confirmed the model rendering or animating.

The truck and actor sequence binding still needs a GameCube runtime capture to prove the models load, animate, and switch bodygroups correctly. The new composite actor is in the map manifest, but has not been observed in game.
