## Retail `connect_paths` / `disconnect_paths` route blockers

Implemented temporary MOHAA path blockers using the target entity's world bounds. During graph construction, a trace blocked by a named solid brush retains that candidate edge and registers the brush as initially closed; this lets a later `connect_paths` restore a link that otherwise would never enter the graph. `disconnect_paths` activates the entity's bounds filter, and `connect_paths` removes it. Removing a blocker entity also clears it. If every graph route is blocked, the actor is stopped and the script command reports an error instead of falling back to a straight path through the closed obstacle. The staged m1l2a `global/disc.scr` uses this lifecycle: make the door solid, disconnect its paths, then door scripts reconnect paths after opening.

Native ASan/UBSan regressions verify a blocked direct edge selects an alternate route, reopening restores the direct route, a fully blocked graph refuses movement, and entity removal clears stale blockers. The isolated path-blocker test and all native MOHAA script cases except the unrelated soundtrack prefix assertion pass; the existing full harness still stops at `test_music`. The modified VM passes a devkitPPC `-fsyntax-only -Wall -Wextra -Werror` compile, and the modified entity binding passes GameCube-target C++ syntax-only compilation against the pinned SDK headers. Runtime validation on actual campaign gates/doors and GameCube remains open; bounds-based blocking is an approximation and has not yet been compared with retail path-node link behavior.

## Retail actor `accuracy` command (partial combat implementation)

Traced `accuracy` through retail campaign scripts and implemented `$actor accuracy N` for scripted grunts. The VM validates values from 0 through 300, and the game DLL applies the value only to MOHAA scripted actors. At 100, their existing global-skill hit curve is unchanged; positive values scale that curve and it remains clamped to 5–95%; zero disables their hits. Ordinary DoD grunts retain their previous calculation and RNG behavior.

This interpretation is an engine-side approximation, not verified retail math. Retail scripts also pass `accuracy` to mounted gunner entities (for example `global/mg42.scr`), whose weapon-control behavior is not implemented by the grunt actor backend. This change therefore covers scripted grunt actors only; mounted weapons and their retail firing behavior remain open.
