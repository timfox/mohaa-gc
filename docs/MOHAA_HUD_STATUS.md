# MOHAA compass and scripted tips

## Current implementation

The GameCube client draws a MOHAA compass in the upper-left corner. The retail face and objective arrow are baked into 16 orientation frames so the GameCube renderer does not need runtime sprite rotation. The stationary bronze housing and needle now keep 64-pixel source detail; the rotating layers remain 32 pixels to bound MEM1 use. The objective arrow loads only after the active mission sets a compass target.

The MOHAA script VM now handles the retail `huddraw_*` slot commands and routes `iprintlnbold` / `iprintlnbold_noloc` to a five-second gameplay tip. It concatenates multi-argument tips like the retail VM print routine. Tips are left-aligned under the compass and use a dark offset for readability; wrapping uses the active font's pixel widths and the remaining viewport width. The HUD draw runs on the MOHAA branch of the lean client redraw path. Menu-like shader slots are also supported through converted MOHAA sprite textures.

The retail `set_objective_pos` script command is now bound for both vector and entity arguments. It updates the client compass target, so scripts can steer the objective arrow toward a fixed point or a moving mission actor.

The m1l2a retail script defines `hint_door` but never attaches it to a gameplay event. The script staging step now adds a GameCube-only watcher to the existing `$door_locked` triggers; when one emits the normal `trigger` event, the watcher runs the unchanged retail hint text. Retail source scripts remain untouched. The hook is in [stage_scripts.py](../tools/stage_scripts.py) and is applied by the regular `mohaa_sd.py --stages scripts` path.

The isolated SDK client and script changes are recorded in [the MOHAA retail client integration patch](engine-patches/mohaa-retail-client-integration.patch), based on hlsdk-portable `1b8549e`. The SDK and engine compiled into the candidate DOL. The compass draw path uses each frame's actual sprite dimensions so the 64-pixel housing and needle use the full image. The patch is not yet applied to the canonical SDK checkout.

## Verification

- The GameCube DOL built successfully from isolated source copies; the output used for the probe was `/tmp/mohaa-compass-build/out/mohaagc.dol`.
- A GameCube-aware hybrid ISO booted directly into m1l2a in Dolphin. Runtime log reports the map ready and all four compass sprites loaded (`MOHAA HUD compass: back=1 face=1 needle=1 objective=1`).
- A temporary probe-only copy of `maps/m1l2a.scr` invoked `iprintlnbold` with the retail door instruction. The captured gameplay frame shows the message rendered. The test copy was staged under `/tmp/mohaa-compass-build/data`; retail source assets were not edited.
- A follow-up probe calls `iprintlnbold_noloc` with three text fragments, then runs the existing retail `hint_door` function via the script VM. Dolphin shows the exact retail message and confirms the client-width wrapping path. The injected `thread hint_door` call is only a probe; it does not prove which retail gameplay trigger should invoke that function.
- A separate probe invokes retail `set_objective_pos` with a known vector. The command is no longer reported as unbound, all compass sprites load, and the gameplay capture includes the compass and scripted hint. This proves command dispatch and HUD transport; matching the arrow bearing against a live retail mission target is still open.
- The test map's side/class chooser overlaps part of that message in the captured frame. A separate m1l1 gameplay capture shows the compass unobstructed.
- Follow-up visual refinement scales the 32x32 compact compass sprites to a 48x48 logical display size and positions the retail tip at virtual x=8/y=45, just under the compass as in the supplied retail reference. A new DSI trace showed the MOHAA HUD was skipped because the retail map route entered `CHud::Init` at `gc_quality=1`, selecting the stock full HUD and its uninitialized battery sprite. The client now selects the GameCube lean HUD for MOHAA independently of the generic quality cvar. The 16-frame objective arrow is loaded only after a retail script supplies a target; the m1l1 opening HUD no longer spends ImageLib pool memory on an unused 64 KiB animated sprite. The matched low-memory build uses 256/32 physics limits, three default listen-server slots, and BBA disabled.
- Full-retail m1l1 Dolphin playback now reaches `MAP_READY`, retains XFB presents, loads the MOHAA health/ammo HUD and compass back/face/needle, and renders an in-game frame without the earlier `CHudBattery::Draw` DSI. The [current gameplay still](../media/playtests/screenshots/20261124-032010-m1l1-retail-newgame-hud-lazy-arrow/final.png), [probe log](../media/playtests/notes/20261124-032010-m1l1-retail-newgame-hud-lazy-arrow.md), and [silent capture](../media/playtests/videos/20261124-032010-m1l1-retail-newgame-hud-lazy-arrow-silent.mp4) are archived. The compass is visible, though its edge colors and overall appearance still need comparison/refinement against the retail reference. The updated tip baseline (x=8/y=45) has not yet been captured with the new build.
- The m1l2a listener stages into the map script and the full-physics changelevel route reaches the retail map with a player and weapon HUD. Controller-driven attempts moved the player toward the gate, but the engine safety gate skipped the `trigger_multiple` world-use target; no door-volume touch or hint appeared. The [door-area still](../media/playtests/screenshots/20261124-041356-m1l2a-door-hint-controller/final.png), [silent video](../media/playtests/videos/20261124-041356-m1l2a-door-hint-controller-silent.mp4), and [probe note](../media/playtests/notes/20261124-041356-m1l2a-door-hint-controller.md) are archived.
- The engine-side USE route is restricted to the retail `trigger_multiple` named `door_locked` on m1l2a and within 128 units; the c0a0-only safety gate remains for other interactions. The earlier 508-byte mip-offset null write is guarded in engine commit `136de06` on `codex/smoke-fallback-assets`.
- A clean build exposed a second ABI issue before gameplay: MOHAA’s static game modules use a 256/32 `playermove_t`, while the engine build defaulted to 600/64. `scripts/build-gamecube.sh` now selects 256/32 for the MOHAA profile while preserving explicit overrides. The smoke-disc builder now includes converted `sprites/mohaa/*.spr` assets; before this, the runtime could not load the compass.
- The source-sized retail compass housing and needle need 16 KiB image-pool allocations that fail during m1l2a’s low-MEM1 first HUD draw. `Image_LoadSPR` now retries MOHAA HUD sprites at half resolution after an allocation failure, preserving their display size and higher-resolution source on higher-memory maps. The new 50-second Dolphin run loaded m1l2a, reached gameplay signon 2, loaded all compass layers, showed the compass and health/ammo HUD, and ran through the probe without a panic. Its log records the 64x64→32x32 fallback for the housing and needle. Evidence: [runtime note](../media/playtests/notes/20261124-135543-m1l2a-retailhud-lowmemfix.md), [gameplay still](../media/playtests/screenshots/20261124-135543-m1l2a-retailhud-lowmemfix/final.png), and [silent video](../media/playtests/videos/20261124-135543-m1l2a-retailhud-lowmemfix-silent.mp4).
- The door-hint hook remains unverified in this run: the probe issued USE at the spawn point and logged `world interaction none near origin=(5349,-3867,25)`. Reaching an actual `door_locked` volume and capturing the retail tip is still open.
- Comparing the retail 128x128 housing to the staged 32-pixel asset showed that downsampling erased its fine ring marks. The updated converter emits 64-pixel housing and needle sprites while retaining 32-pixel rotating layers. A first draw attempt sampled only a 32x32 source rectangle; the client now reads each frame's true width and height. The rebuilt DOL (SHA-256 `2a4321cf46edbbf29412746d1325ea9d9efd921cfc12ca60545d16b936825178`) is packaged in the m1l1 smoke ISO (SHA-256 `4627b745d21004ee883445f17ee07961adb7a4aa0dccbd5b776d08bb2b2d82d1`). Dolphin reached `MAP_READY m1l1`, loaded health/ammo HUD and compass back/face/needle, presented frames, and showed the round compass in [the latest still](../media/playtests/screenshots/20261124-035031-m1l1-compass-64-fixed/final.png); the [silent video](../media/playtests/videos/20261124-035031-m1l1-compass-64-fixed-silent.mp4) and [probe note](../media/playtests/notes/20261124-035031-m1l1-compass-64-fixed.md) document this run. The smoke ISO has a reduced map asset set, so this verifies compass loading and layering, not full retail map appearance or hardware memory headroom.
